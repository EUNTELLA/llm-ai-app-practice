# 12장 정리: 벡터 데이터베이스와 멀티모달 검색

## 1. 장의 핵심 주제

12장은 임베딩 벡터를 효율적으로 저장하고 검색하는 방법을 다룬다. 먼저 FAISS를 사용해 로컬 환경에서 벡터 검색 성능을 실험하고, 이후 Pinecone을 사용해 클라우드 기반 벡터 데이터베이스에 임베딩을 저장하고 검색한다.

후반부에서는 텍스트와 이미지를 같은 벡터 공간에서 다루는 CLIP 모델을 활용한다. 이미지로부터 유사한 프롬프트를 검색하고, GPT-4o와 DALL-E 3를 연결해 이미지 설명 및 이미지 생성을 수행하는 멀티모달 파이프라인을 구성한다.

## 2. 사용 라이브러리

주요 라이브러리는 다음과 같다.

- `faiss-cpu`: 벡터 유사도 검색 및 근사 최근접 이웃 검색
- `sentence-transformers`: 문장 임베딩 생성
- `datasets`: 실습용 데이터셋 로드
- `pinecone-client`: Pinecone 벡터 데이터베이스 사용
- `llama-index`: 문서 인덱싱 및 벡터 저장소 연결
- `transformers`: CLIP 텍스트/이미지 인코더 사용
- `openai`: GPT-4o, DALL-E 3 API 사용

## 3. FAISS를 이용한 벡터 검색

FAISS는 대량의 벡터에서 빠르게 유사 벡터를 찾기 위한 라이브러리다. 12장에서는 SIFT1M 데이터셋을 사용해 벡터 검색을 실습한다.

실습 흐름은 다음과 같다.

1. SIFT1M 데이터셋 다운로드
2. 질의 벡터, 데이터베이스 벡터, 정답 데이터 로드
3. `IndexFlatL2` 인덱스 생성
4. 데이터 개수를 늘려가며 색인 시간, 검색 시간, 메모리 사용량 측정

`IndexFlatL2`는 모든 벡터와의 거리를 직접 계산하는 정확한 검색 방식이다. 정확도는 높지만 데이터가 커질수록 검색 비용이 증가한다.

## 4. HNSW 기반 근사 최근접 이웃 검색

HNSW는 그래프 기반 근사 최근접 이웃 검색 알고리즘이다. 전체 벡터를 모두 비교하지 않고, 그래프를 따라 이동하면서 가까운 벡터를 찾기 때문에 대규모 데이터에서 빠른 검색이 가능하다.

FAISS에서는 다음과 같이 HNSW 인덱스를 생성한다.

```python
index = faiss.IndexHNSWFlat(d, m)
```

여기서 `d`는 벡터 차원, `m`은 각 노드가 연결할 이웃 수를 의미한다.

### M 파라미터

`M`은 HNSW 그래프에서 각 노드가 유지하는 연결 수와 관련된다.

- 값이 커지면 검색 정확도가 높아질 수 있다.
- 대신 인덱스 생성 시간과 메모리 사용량이 증가한다.
- 너무 작으면 그래프 연결성이 낮아져 검색 품질이 떨어질 수 있다.

실습에서는 `M = 8, 16, 32, 64`를 비교한다.

### efConstruction 파라미터

`efConstruction`은 인덱스를 만들 때 후보를 얼마나 넓게 탐색할지 결정한다.

- 값이 클수록 더 품질 좋은 그래프가 만들어진다.
- 검색 정확도는 좋아질 수 있지만 인덱스 생성 시간이 길어진다.
- 색인 단계의 비용과 검색 품질 사이의 균형을 조절하는 파라미터다.

실습에서는 `efConstruction = 40, 80, 160, 320`을 비교한다.

### efSearch 파라미터

`efSearch`는 검색 시 탐색할 후보 수를 조절한다.

- 값이 클수록 더 많은 후보를 확인하므로 재현율이 높아진다.
- 대신 쿼리당 검색 시간이 증가한다.
- 검색 시점의 속도와 정확도 사이의 균형을 조절한다.

실습에서는 `efSearch = 16, 32, 64, 128`을 비교한다.

## 5. 검색 성능 평가 지표

실습에서는 주로 다음 항목을 확인한다.

- 색인 시간: 벡터를 인덱스에 추가하는 데 걸린 시간
- 검색 시간: 쿼리 하나를 처리하는 데 걸린 평균 시간
- 메모리 사용량: 인덱스 생성 전후의 메모리 차이
- `R@1`: 가장 가까운 1개 검색 결과가 정답과 일치하는 비율

`R@1` 값이 높을수록 검색 결과의 정확도가 높다고 볼 수 있다.

## 6. Pinecone 벡터 데이터베이스

Pinecone은 벡터를 저장하고 유사도 검색을 수행하는 클라우드 기반 벡터 데이터베이스다. FAISS가 로컬 실험과 라이브러리 중심이라면, Pinecone은 실제 서비스에서 벡터 검색 기능을 운영하기 위한 관리형 데이터베이스에 가깝다.

기본 흐름은 다음과 같다.

1. Pinecone API 키 설정
2. 인덱스 생성
3. 임베딩 벡터 생성
4. Pinecone 입력 형식으로 데이터 변환
5. 벡터 업로드
6. 쿼리 벡터로 유사 데이터 검색
7. 데이터 업데이트 및 삭제

Pinecone에 저장하는 데이터는 보통 다음 구조를 가진다.

```python
{
    "id": "문서 ID",
    "values": [0.1, 0.2, ...],
    "metadata": {
        "text": "원본 문장"
    }
}
```

`values`에는 임베딩 벡터가 들어가고, `metadata`에는 검색 결과를 해석하기 위한 원본 텍스트나 기타 정보를 저장한다.

## 7. 문장 임베딩 생성

한국어 문장 임베딩 생성을 위해 `SentenceTransformer` 모델을 사용한다.

```python
sentence_model = SentenceTransformer("snunlp/KR-SBERT-V40K-klueNLI-augSTS")
```

실습에서는 `klue` 데이터셋의 문장을 불러와 임베딩 벡터로 변환한다. 이후 각 문장을 Pinecone에 저장하고, 특정 문장의 임베딩을 쿼리로 사용해 유사 문장을 검색한다.

## 8. Pinecone에서 검색, 수정, 삭제

Pinecone의 주요 작업은 다음과 같다.

### 검색

```python
index.query(
    namespace="llm-book-sub",
    top_k=10,
    include_values=True,
    include_metadata=True,
    vector=embeddings[0]
)
```

`top_k`는 반환할 검색 결과 개수를 의미한다. `include_metadata=True`를 사용하면 저장된 원본 문장 같은 메타데이터를 함께 확인할 수 있다.

### 수정

```python
index.update(
    id="기존_문서_id",
    values=new_embedding,
    set_metadata={"text": new_text},
    namespace="llm-book-sub"
)
```

기존 문서의 임베딩 벡터와 메타데이터를 업데이트할 수 있다.

### 삭제

```python
index.delete(
    ids=["기존_문서_id"],
    namespace="llm-book-sub"
)
```

저장된 벡터를 ID 기준으로 삭제한다.

## 9. LlamaIndex와 Pinecone 연결

LlamaIndex는 문서를 인덱싱하고 검색 기반 애플리케이션을 만들기 위한 프레임워크다. Pinecone을 벡터 저장소로 연결하면 문서 임베딩을 외부 벡터 DB에 저장할 수 있다.

핵심 구조는 다음과 같다.

```python
vector_store = PineconeVectorStore(pinecone_index=pinecone_index)
storage_context = StorageContext.from_defaults(vector_store=vector_store)
index = VectorStoreIndex.from_documents(
    documents,
    storage_context=storage_context
)
```

이 구조는 RAG 시스템에서 자주 사용된다. 문서를 임베딩하고, 벡터 DB에서 관련 문서를 검색한 뒤, LLM이 검색 결과를 바탕으로 답변을 생성하는 방식이다.

## 10. 멀티모달 데이터셋과 이미지 설명

후반부에서는 `DiffusionDB` 데이터셋을 사용한다. 이 데이터셋에는 이미지와 해당 이미지를 생성하는 데 사용된 프롬프트가 포함되어 있다.

실습에서는 특정 이미지를 선택하고, 다음 작업을 수행한다.

1. 원본 이미지와 원본 프롬프트 확인
2. 이미지를 base64 형식으로 변환
3. GPT-4o에 이미지를 입력해 이미지 설명 생성

GPT-4o는 이미지를 이해하고 자연어 설명을 생성할 수 있으므로, 이미지 내용을 텍스트 프롬프트처럼 활용할 수 있다.

## 11. CLIP을 이용한 텍스트와 이미지 임베딩

CLIP은 텍스트와 이미지를 같은 의미 공간에 매핑하는 모델이다. 즉, 이미지 임베딩과 텍스트 임베딩을 서로 비교할 수 있다.

실습에서는 `openai/clip-vit-base-patch32` 모델을 사용한다.

### 텍스트 임베딩

DiffusionDB의 프롬프트를 CLIP 텍스트 인코더로 변환한다.

```python
text_model = CLIPTextModelWithProjection.from_pretrained(
    "openai/clip-vit-base-patch32"
)
```

생성된 텍스트 임베딩은 Pinecone 인덱스에 저장된다. 이때 인덱스 차원은 CLIP 임베딩 차원인 512로 설정한다.

### 이미지 임베딩

원본 이미지를 CLIP 이미지 인코더로 변환한다.

```python
vision_model = CLIPVisionModelWithProjection.from_pretrained(
    "openai/clip-vit-base-patch32"
)
```

이미지 임베딩을 쿼리로 사용하면, Pinecone에 저장된 텍스트 프롬프트 임베딩 중 이미지와 의미적으로 가까운 프롬프트를 검색할 수 있다.

## 12. 이미지 기반 프롬프트 검색

이미지를 CLIP으로 임베딩한 뒤 Pinecone에서 검색하면, 이미지와 유사한 의미를 가진 프롬프트를 찾을 수 있다.

```python
search_results = index.query(
    vector=image_embeds[0].tolist(),
    top_k=3,
    include_values=False,
    include_metadata=True
)
```

검색 결과에는 유사한 프롬프트와 점수가 포함된다. 이 방식은 이미지 검색, 유사 이미지 추천, 프롬프트 복원, 멀티모달 RAG 등에 활용될 수 있다.

## 13. DALL-E 3를 이용한 이미지 생성

마지막 실습에서는 세 가지 프롬프트를 사용해 이미지를 생성한다.

1. GPT-4o가 원본 이미지를 설명한 텍스트
2. DiffusionDB에 포함된 원본 프롬프트
3. 이미지 임베딩 검색으로 찾은 유사 프롬프트

각 프롬프트를 DALL-E 3에 입력해 이미지를 생성한 뒤, 원본 이미지와 나란히 출력하여 비교한다.

이를 통해 같은 이미지에서 출발하더라도 다음과 같은 접근 방식에 따라 결과가 달라질 수 있음을 확인한다.

- 사람이 작성한 원본 프롬프트
- 모델이 이미지를 보고 생성한 설명
- CLIP 임베딩 검색으로 찾은 유사 프롬프트

## 14. 전체 실습 흐름 요약

12장의 전체 흐름은 다음과 같다.

1. FAISS로 벡터 검색의 기본 원리와 성능을 확인한다.
2. HNSW 파라미터를 조정하며 근사 검색의 속도와 정확도 균형을 실험한다.
3. Pinecone에 문장 임베딩을 저장하고 검색한다.
4. Pinecone에서 벡터 데이터의 수정과 삭제를 실습한다.
5. LlamaIndex와 Pinecone을 연결해 RAG 구조를 준비한다.
6. DiffusionDB 이미지와 프롬프트 데이터를 사용한다.
7. GPT-4o로 이미지 설명을 생성한다.
8. CLIP으로 텍스트와 이미지를 같은 벡터 공간에 임베딩한다.
9. 이미지 임베딩으로 유사 프롬프트를 검색한다.
10. DALL-E 3로 여러 프롬프트 기반 이미지를 생성해 비교한다.

## 15. 핵심 개념 정리

### 벡터 검색

텍스트, 이미지, 문서 등을 임베딩 벡터로 변환한 뒤, 벡터 간 거리를 기준으로 유사한 데이터를 찾는 방식이다.

### 정확 검색과 근사 검색

정확 검색은 모든 벡터를 비교하므로 정확하지만 느릴 수 있다. 근사 검색은 일부 후보만 탐색해 빠르게 검색하지만 정확도가 약간 낮아질 수 있다.

### HNSW

그래프 기반 근사 최근접 이웃 검색 알고리즘이다. 대규모 벡터 검색에서 속도와 정확도의 균형이 좋아 널리 사용된다.

### 벡터 데이터베이스

임베딩 벡터와 메타데이터를 저장하고, 유사도 검색을 제공하는 데이터베이스다. Pinecone, Weaviate, Milvus, Chroma 등이 대표적이다.

### CLIP

이미지와 텍스트를 같은 벡터 공간에 배치하는 멀티모달 모델이다. 이미지로 텍스트를 검색하거나, 텍스트로 이미지를 검색하는 데 사용할 수 있다.

### 멀티모달 파이프라인

텍스트와 이미지처럼 서로 다른 형태의 데이터를 함께 처리하는 구조다. 12장에서는 이미지 설명 생성, 이미지 임베딩 검색, 프롬프트 기반 이미지 생성을 연결한다.

## 16. 결론

12장은 벡터 검색을 실제 애플리케이션 수준으로 확장하는 방법을 보여준다. FAISS를 통해 검색 알고리즘의 동작과 성능 특성을 이해하고, Pinecone을 통해 벡터 데이터베이스를 사용하는 방법을 익힌다.

또한 CLIP, GPT-4o, DALL-E 3를 함께 사용해 이미지와 텍스트를 연결하는 멀티모달 검색 및 생성 흐름을 구성한다. 이 내용은 RAG, 의미 검색, 이미지 검색, 프롬프트 검색, 추천 시스템, 생성형 AI 애플리케이션의 기반 기술로 활용될 수 있다.
